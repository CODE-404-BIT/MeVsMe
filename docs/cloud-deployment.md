# Free cloud deployment

Status: local cloud preparation and verification completed on 2026-09-19. **Not yet published**: Render/Neon access and a private source repository are not connected.

Use **Render Free** for the private dashboard and **Neon Free** for the database. The Windows launcher continues using `data/app.db`. Cloud data uses PostgreSQL and survives web-service restarts. Local and cloud copies do not automatically synchronise.

## Accounts and source

1. Create/sign in to your GitHub, Neon and Render accounts. Choose only Free plans. Keep usage spending disabled; do not enable paid upgrades.
2. Create a private source repository containing this project's source/configuration files. Exclude `data`, `.venv`, `.env*`, database backups, logs and credentials. The supplied `.gitignore` covers these. Render needs access to that private repository.
3. In Neon, create an empty Free PostgreSQL project near your Render region. In Connect, disable connection pooling and copy the **direct** connection URL with `sslmode=require`. Session advisory locks require a direct connection; a `-pooler` hostname is rejected. The application's own connection pool is limited to three connections.

## Migrate your existing data before starting Render

Use PowerShell in the project directory. Never paste secret values into chat or commit them.

```powershell
.\.venv\Scripts\python.exe -m pip install -e '.[cloud]'
.\.venv\Scripts\python.exe -c "from pathlib import Path; from betmodel.migrate_cloud import backup_sqlite; from datetime import datetime; p=Path('data/backups/cloud-'+datetime.now().strftime('%Y%m%d-%H%M%S')+'.db'); backup_sqlite(Path('data/app.db'),p); print(p)"
```

Use the backup path printed above as SOURCE below. Enter the Neon connection URL without displaying it:

```powershell
$cloudDbSecret = Read-Host 'Neon direct connection URL' -AsSecureString
$env:DATABASE_URL = [System.Net.NetworkCredential]::new('', $cloudDbSecret).Password
.\.venv\Scripts\python.exe -m betmodel.migrate_cloud --source SOURCE --state-root . --dry-run
.\.venv\Scripts\python.exe -m betmodel.migrate_cloud --source SOURCE --state-root . --apply
Remove-Item Env:DATABASE_URL
```

Migration refuses any destination containing application rows. It imports all known tables in one transaction, retains IDs, resets sequences and compares saved prediction JSON. A failure rolls back imported rows; empty schema tables may remain. Do not start Render before migration, since it creates operational state. Keep the local backup. Existing report metadata can be imported using `--state-root`; runtime checkpoints in newer backups migrate automatically. In-memory checkpoints from an old running server cannot be recovered from SQLite.

## Configure Render

Create a new Blueprint from the private repository and its `render.yaml`. Confirm the displayed service plan says **Free** before creating it. No Render database, paid disk, worker or cron job is needed. `.python-version` selects Python 3.12.

Set the requested secrets:

- `DATABASE_URL`: the same Neon direct TLS URL.
- `DASHBOARD_PASSWORD_HASH`: generate locally with the following command. Enter a strong password when prompted; save the printed hash in Render, not the plaintext password.
- `DASHBOARD_SECRET_KEY`: generated by the Blueprint; retain it across redeploys.
- `API_FOOTBALL_KEY`: your provider key, or blank for browsing saved records.

```powershell
.\.venv\Scripts\python.exe -c "from getpass import getpass; from werkzeug.security import generate_password_hash; print(generate_password_hash(getpass('Dashboard password: ')))"
```

Render supplies `RENDER_EXTERNAL_HOSTNAME`; the app derives its HTTPS origin. Optional `PUBLIC_ORIGIN` must be the exact HTTPS origin with no path. Missing or invalid database/login/origin configuration prevents startup. The app never falls back to SQLite in cloud mode.

Once Render reports healthy, open its HTTPS URL and sign in. The normal Matches, Research, 2×/3× and Prediction History screens work behind login. Sign out with the sidebar button. Sessions last up to eight hours and are revoked on logout. Ten failed login attempts temporarily block further attempts for fifteen minutes; this is a global single-owner limit, so spoofed forwarding headers cannot bypass it.

## Free-tier behavior and recovery

Render Free sleeps after 15 idle minutes; waking can take about a minute. Its local files are temporary, so records, research reports and metered response caches are in Neon. Jobs can be interrupted by sleep/redeploy; the dashboard reports interruption and allows a retry. There is no guaranteed background scheduler. Football API quotas still apply. No automatic paid upgrade is configured. Free plans may suspend service when allowances are exhausted.

Monitor Neon storage and compute in its dashboard. Historical records grow over time; the free allocation is finite. Expired operational cache entries are removed during normal state writes. Do not remove prediction records merely to improve measured accuracy.

To return to local use, open `Launch Dashboard.vbs`; its SQLite database is unchanged by the cloud import. Any new cloud records must be exported/backed up separately before deleting a Neon project. Do not migrate into a populated database or expect local changes to appear automatically in the cloud.
